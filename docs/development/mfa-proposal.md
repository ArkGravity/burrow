# MFA 认证与恢复

状态：2026-10-02，已在移除上游 Provider 后的密码认证上实现全员强制 MFA；用户确认浏览器人工验收通过。自动化验证记录见 [验证报告](../testing/oidc-conformance.md)。

## 范围

所有用户（包括 Administrator）强制使用 TOTP 认证器。新用户首次登录、已有用户升级后首次重新登录和管理员重置 MFA 后的首次登录，都必须完成绑定。第一版每个账号绑定一个 TOTP 密钥，不提供跳过、用户关闭、信任设备或自助恢复码。

认证器参数为 HMAC-SHA-1、6 位数字、30 秒周期，允许前后一个周期的时钟偏差。绑定页提供本地生成的二维码和手动输入密钥，用户输入正确验证码后才保存有效绑定。[RFC 6238](https://datatracker.ietf.org/doc/html/rfc6238) 定义了 TOTP 的算法、时间步长和成功验证后阻止重复接受的要求。

## 用户流程

| 用户状态             | 顺序                                                            |
| -------------------- | --------------------------------------------------------------- |
| 未绑定，正常密码     | 验证密码 → 扫码绑定并验证动态码 → 建立正式会话                  |
| 未绑定，临时密码     | 验证临时密码 → 强制改密 → 扫码绑定并验证动态码 → 建立正式会话   |
| 已绑定，正常密码     | 验证密码 → 验证 MFA → 建立正式会话                              |
| 已绑定，密码被重置   | 验证临时密码 → 验证原 MFA → 强制改密 → 建立正式会话             |
| MFA 被重置，密码正常 | 验证原密码 → 强制重新绑定并验证 MFA → 建立正式会话              |
| 密码和 MFA 都被重置  | 验证临时密码 → 强制改密 → 强制重新绑定并验证 MFA → 建立正式会话 |

密码验证通过后，只建立受限的短期登录事务，有效期固定为 5 分钟。事务绑定浏览器、账号、当前认证版本及合法的 OIDC 请求，只允许当前步骤所需的验证、改密、绑定和取消。未完成全部步骤时不能访问门户、资料或管理 API，不能签发 OIDC 授权码或 Token。前端刷新页面可以恢复当前步骤；过期、取消或达到错误次数上限后，需要重新验证密码。强制改密成功后撤销其他会话/旧事务，并轮换当前受限凭据。

从应用发起的登录保留服务端验证过的 `requestId`，完成后继续原授权请求；原 OIDC 请求过期则需要从应用重新发起。已完成 MFA 的有效 Burrow 会话继续支持应用间 SSO；`prompt=login` / `max_age` 触发的新认证必须重新完成密码和 MFA。`prompt=none` 在缺少完整会话时返回 `login_required`。

## MFA 丢失与管理员恢复

登录页提示用户联系管理员，由管理员在线下核实身份。只有 Administrator 可在用户管理中执行「重置 MFA」，普通 `users:write` 不足以执行。在线重置需要操作者已经完成 MFA，并再次提交当前有效且未使用的 TOTP 验证码及重置原因。

重置在同一事务内完成：重新检查操作者权限和验证码、清除目标用户的密钥、递增认证版本、撤销全部 Burrow 会话与 Token、删除未完成的登录/绑定/OIDC 授权事务、提交不含秘密的审计记录。审计失败则全部回滚。认证版本使重置前已验证密码的旧事务无法重新写回密钥或建立会话。

MFA 重置保留原密码。密码重置保留原 MFA，并继续强制改密；两者都丢失时，管理员分别执行两个操作。第一版不向知道密码的用户提供直接清除 MFA 的入口。[OWASP MFA 指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html) 说明了恢复入口避免绕过额外认证的重要性。

唯一管理员丢失 MFA 时，服务器运维人员可以使用`burrow mfa-reset --username <账号> --reason <原因>`。命令复用配置和数据库事务，记录运维恢复审计，不打印密钥或生成密码，不自动开启账号。恢复后的登录仍必须验证密码并绑定新 MFA。它是拥有服务器和数据库权限人员的恢复操作，不开放对应匿名 HTTP API。

重置只能立即控制 Burrow 的会话、换码和 UserInfo；下游应用自己的会话以及已经签发、离线验证的 ID Token 按当前应用会话边界处理，不增加跨应用同步退出。

## 持久化、接口和保护

新增显式迁移 `005_mandatory_mfa.sql`，schema v5，不修改迁移 001–004。保存用户的 MFA 认证版本、加密的 TOTP 密钥、最后成功使用的时间步，以及具有过期时间的登录事务；会话记录 MFA 完成时间和对应版本。临时绑定密钥同样加密，使用现有 master key；列表接口、日志和审计不能返回密钥或验证码。

扩展 `/auth/login` 返回下一步状态；新增以下受限事务和管理员重置接口。正式 `/me` 返回当前 MFA 状态。受限凭据和正式会话使用独立的 host-only、HttpOnly、SameSite=Lax Cookie，生产启用 Secure；继续执行 CSRF 和 Origin 检查。

每个事务最多接受 5 次错误验证码，并按账号和可信客户端 IP 限制请求及事务签发速率，防止通过不断重新登录绕过尝试上限。事务消费、绑定确认和 TOTP 时间步更新必须原子执行，同一账号、同一时间步的验证码只能成功使用一次（包括绑定、登录和敏感重置）。取消、重复提交和并发操作不得覆盖已有有效绑定。

每次完成认证时重新检查账号、密码/认证版本、事务有效性和目标应用。管理操作继续在事务内检查当前权限。正式会话读取、OIDC 授权、授权码兑换和 UserInfo 都检查 MFA 已完成且认证版本仍有效。继续使用现有 OP 适配和严格 PKCE；OIDC `auth_time` 对应完整认证时间，认证方式记录密码和 OTP，避免宣称上游认证或未定义的 ACR 等级。

## 升级和验证

升级时不自动生成用户 MFA 密钥；已有用户进入未绑定状态。旧的未完成 MFA 的 Burrow 会话与 Token 失效，未兑换授权码及未完成授权事务失效，用户重新验证密码后绑定。保留账号、密码、角色、组、应用配置和签名密钥。升级不会立即清除应用自己保存的会话。

验证覆盖 SQLite 和 PostgreSQL 的绑定、验证、防重放、并发单次消费、认证版本复查、权限撤销、会话撤销和审计失败回滚。浏览器覆盖首次绑定、刷新与过期、临时密码改密顺序、重置后重新绑定、绕过受限事务的拒绝、从应用发起的授权继续和完成 MFA 后的共享 SSO。包含管理员丢失 MFA 的 CLI 恢复与命令失败回滚。

## API 与实现细节

所有路径的 API 前缀为 `/api/v1`：

| 方法 | 路径                    | 作用                                                                                           |
| ---- | ----------------------- | ---------------------------------------------------------------------------------------------- |
| POST | `/auth/login`           | 验证密码，创建受限事务；返回 `step`、`expiresAt` 和 `requestId`                                |
| GET  | `/auth/login/status`    | 恢复当前步骤，不返回密码、验证码或绑定密钥                                                     |
| POST | `/auth/login/bind`      | 仅在 `bind` 步骤生成或读取当前事务的加密待绑定密钥，返回本地二维码所需的 `uri` 和手动 `secret` |
| POST | `/auth/login/verify`    | 提交 `code`，完成绑定或已绑定 MFA 验证；原子记录已用时间步                                     |
| POST | `/auth/login/password`  | 仅在 `password` 步骤提交新 `password`；轮换受限凭据且不延长服务端期限                          |
| POST | `/auth/login/cancel`    | 删除当前受限事务和 Cookie                                                                      |
| POST | `/users/{id}/mfa-reset` | Administrator 提交自己的 `code` 和非空 `reason`（最多 500 字节）                               |

下一步为 `password`、`bind`、`verify` 或 `complete`。仅 `complete` 返回经服务端验证的后续地址并签发正式会话；前端在 `/change-password` 和 `/mfa` 恢复当前步骤。二维码由已有 Ant Design `QRCode` 本地生成，无第三方二维码服务或新依赖。TOTP 使用 Go 标准库实现 RFC 4226/6238，并以官方 SHA-1 向量的六位结果及窗口/重放测试校验。

每分钟同一可信 IP 最多 30 次密码登录，同一精确用户名最多 30 次；MFA 验证按 IP 最多 30 次、按账号最多 10 次，管理员重置也共享账号 MFA 计数；受限改密需先验证当前步骤，并按账号/IP 各限制为每分钟 30 次。事务额外限制 5 次错误码。这些速率桶使用现有单实例进程内计数，进程重启会清空；最后已用时间步和事务错误次数在数据库中持久化。PostgreSQL 的认证修改、管理修改与 CLI 恢复使用同一事务级 advisory lock，SQLite 使用现有即时写事务；原子时间步条件更新进一步阻止重放。

`BURROW_LOGIN_TTL` / `oidc.login_ttl` 继续只控制 OIDC 请求事务（默认 10 分钟），受限密码/MFA 登录固定为 5 分钟。清理器删除过期登录事务；到期检查立即生效，不依赖清理周期。运维恢复命令、升级步骤和回滚边界见 [恢复文档](../operations/recovery.md#mandatory-mfa-upgrade-and-recovery)。
