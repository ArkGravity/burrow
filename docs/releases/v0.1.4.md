# Burrow v0.1.4

This patch release improves documentation and onboarding, introduces contribution
and private vulnerability reporting guides, and aligns the Go module with the
current repository. Authentication behavior and schema v5 are unchanged.

## Changes

- Reorganize the English and Chinese READMEs around product scope, installation,
  first login and application access. Keep four badges for CI, release, Go and MIT.
- Add browsable [English](https://github.com/ArkGravity/burrow/blob/v0.1.4/docs/installation.md) and [Chinese](https://github.com/ArkGravity/burrow/blob/v0.1.4/docs/installation_zh.md)
  installation guides, covering Compose, Linux binaries, MFA and upgrades.
- Move detailed source-development, configuration, build and test instructions to
  the [development guide](https://github.com/ArkGravity/burrow/blob/v0.1.4/docs/development/getting-started.md).
- Add [Contributing](https://github.com/ArkGravity/burrow/blob/v0.1.4/CONTRIBUTING.md) and [Security](https://github.com/ArkGravity/burrow/blob/v0.1.4/SECURITY.md), with
  GitHub private vulnerability reporting enabled for the repository.
- Update the documentation index, CI deployment reference and packaged installation
  guide. Quick-start examples pin the new version while release navigation stays stable.
- Change the Go module and three internal imports from `github.com/logic3579/burrow`
  to `github.com/ArkGravity/burrow`; remove unused dependency declarations and checksums.
  Source consumers should update any imports using the old module path.

## Install

Docker Compose is recommended; published images and binaries include the frontend
and do not require Go or Bun at runtime. Linux amd64 and arm64 use these image tags:

```text
ghcr.io/arkgravity/burrow:v0.1.4
docker.io/logic3579/burrow:v0.1.4
```

Release attachments:

- `burrow_v0.1.4_linux_amd64.tar.gz`
- `burrow_v0.1.4_linux_arm64.tar.gz`
- `burrow_v0.1.4_deploy.tar.gz`
- `INSTALL.md`
- `IMAGES.txt`
- `SHA256SUMS`

Use the [installation guide](https://github.com/ArkGravity/burrow/blob/v0.1.4/docs/installation.md) or the attached version-specific
instructions. Pin the image tag or the digest from `IMAGES.txt`. Native Linux
binaries require glibc 2.36+.

## Upgrade

Back up the database, original master key and configuration. Select the new image
or binary, then run migration, seed and the server in order. Existing users,
passwords, grants, signing keys and authenticator bindings are preserved.

MFA remains disabled by default. To require it, explicitly set
`security.mfa_enabled: true` or `BURROW_MFA_ENABLED=true` before startup.
This is especially relevant when upgrading from v0.1.0 or v0.1.1, which required MFA.
See [upgrade and recovery guidance](https://github.com/ArkGravity/burrow/blob/v0.1.4/docs/operations/recovery.md).

## Verification scope

Publication requires successful CI for the exact main commit and successful native
amd64/arm64 release preparation. The workflow tests the packaged binaries with
SQLite/MFA/OIDC browser flows, smoke-tests production containers with PostgreSQL,
and publishes the tested images without rebuilding. Publication results are
recorded in the [verification report](https://github.com/ArkGravity/burrow/blob/main/docs/testing/oidc-conformance.md).

Automated interoperability tests and historical manual acceptance do not constitute
OpenID Foundation certification or validation of your production deployment.
